5

Configurar Git

Ya tenemos Git instalado. Antes de comenzar nuestro proyecto, debemos indicarle a Git quién está realizando los cambios. Para ello configuraremos nuestro nombre y nuestro correo electrónico.

PASO 1 — Abrir Git Bash

Abrimos el menú de Inicio de Windows y buscamos:

Git Bash

Hacemos clic para abrir la terminal.

PASO 2 — Configurar nuestro nombre

Primero configuraremos el nombre que aparecerá como autor de nuestros cambios.

Copiamos el siguiente comando: 

git config --global user.name "TU NOMBRE"

Reemplazamos TU NOMBRE por nuestro nombre.

Después presionamos Enter.

¿Para qué sirve este nombre?

Cada vez que guardemos una versión de nuestro proyecto mediante un commit, Git registrará quién realizó ese cambio.

Por eso debemos configurar nuestra identidad antes de comenzar a trabajar con el proyecto.

PASO 3 — Configurar nuestro correo

Ahora configuraremos el correo electrónico que Git asociará con nuestros cambios.

Copiamos: 

git config --global user.email "TU_CORREO"

Reemplazamos TU_CORREO por nuestro correo electrónico.

Después presionamos Enter.

¿Tiene relación con nuestra cuenta de GitHub?

Sí. Es recomendable utilizar un correo que tengamos agregado y verificado en nuestra cuenta de GitHub.

De esta manera, cuando más adelante enviemos nuestros commits a GitHub, GitHub podrá relacionarlos con nuestra cuenta.

Si creamos nuestra cuenta de GitHub utilizando Google, podemos utilizar el correo asociado a esa cuenta.

PASO 4 — Revisar la configuración

Ahora comprobaremos que Git guardó correctamente nuestros datos.

Escribimos: 

git config --global --list

Presionamos Enter.

Entre la información debemos encontrar:

user.name=...

user.email=...

Recuerda

Git trabaja en nuestra computadora y utiliza nuestro nombre y correo para identificar quién realizó cada cambio.

GitHub lo utilizaremos más adelante para guardar nuestro repositorio en Internet y compartir nuestro proyecto.

Por ahora solamente estamos configurando nuestra identidad en Git.

✓ Resultado

Git ya tiene configurado nuestro nombre y nuestro correo electrónico. Estamos listos para comenzar a trabajar con nuestro proyecto.

Crear e iniciar nuestro proyecto con Git

Ya sabemos qué página quiere nuestro cliente. Ahora crearemos una carpeta para guardar todo el proyecto de Aroma Café y después haremos que Git comience a controlar los cambios que realicemos dentro de ella.

PASO 1 — Crear una carpeta

Creamos una nueva carpeta para nuestro proyecto.

Colocamos como nombre: 

aroma-cafe

Esta carpeta guardará todos los archivos que iremos creando para la página web.

PASO 2 — Abrir Git Bash

Hacemos clic derecho sobre la carpeta aroma-cafe.

Seleccionamos:

Open Git Bash here

Se abrirá una terminal de Git Bash directamente en nuestra carpeta.

PASO 3 — Inicializar Git

Ahora debemos indicarle a Git que queremos comenzar a utilizarlo en esta carpeta.

Copiamos el siguiente comando: 

git init

Pegamos el comando en Git Bash y presionamos Enter.

¿Qué significa git init?

git

Indica que vamos a utilizar Git.

init

Viene de initialize, que significa inicializar.

Por lo tanto, git init significa que estamos iniciando Git en esta carpeta.

PASO 4 — ¿Qué ocurrió?

Después de ejecutar el comando, Git convierte nuestra carpeta aroma-cafe en un repositorio Git.

Un repositorio es nuestro proyecto preparado para que Git pueda registrar y controlar los cambios que iremos realizando.

Git también crea automáticamente dentro del proyecto una carpeta especial llamada: 

.git

Esta carpeta es utilizada por Git para guardar la información necesaria sobre nuestro repositorio. No necesitamos modificarla manualmente.

Idea clave

Ejecutar git init todavía no guarda ninguna versión de nuestra página.

Solamente estamos preparando la carpeta para comenzar a trabajar con Git.

✓ Resultado

Creamos la carpeta aroma-cafe, abrimos Git Bash dentro de ella y ejecutamos git init. Nuestro proyecto ahora es un repositorio Git.

Crear la estructura básica

Nuestro repositorio de Aroma Café ya está iniciado con Git. Ahora crearemos los archivos y carpetas básicos que utilizaremos durante el desarrollo de la página.

PASO 1 — Continuar en Git Bash

Continuamos trabajando en la misma ventana de Git Bash que abrimos dentro de nuestra carpeta aroma-cafe.

Desde aquí crearemos primero los archivos del proyecto.

PASO 2 — Crear los archivos con touch

Utilizaremos el comando touch para crear nuestros archivos.

Copiamos el siguiente comando: 

touch .gitignore .env index.html

Pegamos el comando en Git Bash y presionamos Enter.

¿Qué hace touch?

El comando touch nos permite crear archivos desde Git Bash.

Como escribimos varios nombres después de touch, los tres archivos se crean de una sola vez.

PASO 3 — ¿Qué archivos creamos?

.gitignore

Aquí indicaremos qué archivos o carpetas Git debe ignorar y no incluir en el seguimiento.

.env

Es un archivo que normalmente se utiliza para guardar variables de entorno o información de configuración que no queremos subir al repositorio.

index.html

Será el archivo principal de nuestra página web de Aroma Café.

PASO 4 — Crear las carpetas

Ahora necesitamos tres carpetas para mantener nuestro proyecto organizado.

Utilizaremos el comando mkdir. 

mkdir css img js

Pegamos el comando y presionamos Enter.

¿Qué significa mkdir?

mkdir viene de make directory, que podemos entender como crear directorio o carpeta.

Al escribir css img js después del comando, creamos las tres carpetas de una sola vez.

PASO 5 — ¿Para qué utilizaremos cada carpeta?

css/

Guardaremos los archivos encargados del diseño y apariencia de nuestra página.

img/

Guardaremos las imágenes que utilizaremos en Aroma Café.

js/

Guardaremos los archivos JavaScript que posteriormente agregarán funcionalidad a la página.

PASO 6 — Ver lo que creamos

Para comprobar el contenido de nuestra carpeta, escribimos: 

ls -la

Utilizamos -la porque también queremos visualizar los archivos que comienzan con punto, como .gitignore y .env.

PASO 7 — Nuestra estructura

Nuestro proyecto ahora tiene esta estructura básica: 

aroma-cafe/
├── .gitignore
├── .env
├── index.html
├── css/
├── img/
└── js/

Importante

Por ahora solamente hemos creado la estructura. Los archivos todavía están vacíos y las carpetas todavía no contienen archivos.

Tampoco hemos guardado ningún cambio en el repositorio. Git simplemente está observando nuestro proyecto.

✓ Resultado

Nuestro proyecto de Aroma Café ya tiene una estructura básica con .gitignore, .env, index.html y las carpetas css, img y js.

Aprender a usar .gitignore

En un proyecto no siempre queremos que Git controle todos los archivos y carpetas. Para indicarle cuáles debe ignorar utilizamos un archivo especial llamado .gitignore.

PASO 1 — ¿Qué es .gitignore?

.gitignore es un archivo donde escribimos los nombres de los archivos o carpetas que queremos que Git ignore.

En palabras sencillas

Todo lo que indiquemos correctamente dentro de .gitignore le dice a Git:
“No quiero que controles esto”.

PASO 2 — ¿Por qué ignorar archivos o carpetas?

Algunos elementos existen en nuestra computadora y son necesarios para trabajar, pero no necesitamos guardarlos con Git.

✓ Archivos que pueden contener información privada.

✓ Archivos temporales creados durante el trabajo.

✓ Carpetas generadas automáticamente por algunas herramientas.

✓ Archivos que no necesitamos guardar como parte del proyecto.

Así mantenemos nuestro repositorio más limpio y controlado.

PASO 3 — Abrir .gitignore

Para modificar nuestro archivo .gitignore desde Git Bash utilizaremos Visual Studio Code.

Copiamos: 

code .gitignore

Presionamos Enter.

El archivo .gitignore se abrirá en Visual Studio Code para que podamos modificarlo.

PASO 4 — Ignorar un archivo

En nuestro proyecto tenemos el archivo .env y no queremos que Git realice seguimiento de él.

Dentro de .gitignore escribimos: 

.env

Guardamos con Ctrl + S.

¿Qué significa?

Estamos indicando que el archivo .env debe ser ignorado por Git.

PASO 5 — ¿Cómo se ignora una carpeta?

También podemos ignorar carpetas completas.

Por ejemplo, si existiera una carpeta llamada temporal y quisiéramos ignorarla, podríamos escribir: 

temporal/

La barra / nos ayuda a dejar claro que estamos indicando una carpeta.

Solo es un ejemplo

No necesitamos crear ni agregar temporal/ en nuestro proyecto.
Solo estamos aprendiendo cómo se puede ignorar una carpeta.

Importante

.gitignore no elimina los archivos ni las carpetas.

Los elementos siguen existiendo normalmente en nuestra computadora. Simplemente estamos indicando que Git no debe realizar seguimiento de ellos .

PASO 7 — Así queda nuestro .gitignore

En nuestro proyecto real solamente necesitamos ignorar .env. 

.env

✓ Resultado

Aprendimos que .gitignore sirve para indicar qué archivos o carpetas Git debe ignorar. En nuestro proyecto agregamos .env para que Git no realice seguimiento de ese archivo.

10

Los tres estados de Git

Antes de comenzar a guardar versiones de Aroma Café, necesitamos entender cómo se mueven nuestros archivos dentro de Git. Para aprenderlo de forma sencilla trabajaremos con tres estados.

La idea es muy sencilla

1. Directorio de trabajo

Aquí creamos y modificamos nuestros archivos.

↓

2. Área de preparación

Aquí seleccionamos los cambios que queremos guardar.

↓

3. Repositorio local

Aquí guardamos una versión de esos cambios.

ESTADO 1 — Directorio de trabajo

Es nuestra carpeta del proyecto aroma-cafe, donde trabajamos normalmente.

Aquí podemos crear, escribir, modificar o eliminar archivos.

EJEMPLO

Piensa así:

“Aquí estoy trabajando y haciendo cambios”.

ESTADO 2 — Área de preparación

Después de trabajar podemos decidir qué cambios queremos preparar para la próxima versión.

Los cambios seleccionados pasan al Área de preparación, también conocida como Staging Area.

EJEMPLO

Supongamos que modificamos index.html y otros archivos. Podemos seleccionar cuáles de esos cambios queremos preparar para guardar.

ESTADO 3 — Repositorio local

Finalmente, los cambios que preparamos pueden guardarse como una versión del proyecto.

Esa versión queda registrada dentro de nuestro Repositorio local.

EJEMPLO

Cuando terminemos una parte de Aroma Café, podremos guardar ese momento del proyecto como una versión.

El recorrido de nuestros cambios

DIRECTORIO DE TRABAJO

Trabajamos

↓

ÁREA DE PREPARACIÓN

Seleccionamos

↓

REPOSITORIO LOCAL

Guardamos una versión

Importante

Crear o modificar un archivo no significa que ya guardamos una versión en Git.

Primero trabajamos, después seleccionamos lo que queremos guardar y finalmente guardamos una versión en nuestro repositorio local.

✓ Resultado

Ya entendemos el recorrido básico de nuestros cambios en Git:
→ Directorio de trabajo
→ Área de preparación
→ Repositorio local.

Del Directorio de trabajo al Área de preparación

Nuestros archivos están en el Directorio de trabajo. Ahora aprenderemos a ver qué archivos está detectando Git y después los pasaremos al Área de preparación.

Continuamos trabajando desde Git Bash dentro de nuestro proyecto.

Para saber qué está ocurriendo con nuestros archivos utilizamos: 

git status

Pegamos el comando y presionamos Enter.

¿Qué hace git status?

git status nos muestra el estado actual de nuestro proyecto.

            entrada.target.classList.add("mostrar");
            observador.unobserve(entrada.target);
        }
    });
}, {
    threshold: 0.15
});

secciones.forEach((seccion) => {
    seccion.classList.add("animar");
    observador.observe(seccion);
});

Guardamos con Ctrl + S.

Observa las secciones

JavaScript agrega la clase "mostrar"
